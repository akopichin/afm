# Переписать дашборд afm на React (Vite SPA, TypeScript)

## Current State

`pkg/web/dashboard` — статический веб-дашборд afm на ванильном JS (`app.js`, ~1500 строк), встраиваемый в
бинарник клеточкой `pkg/web` через `//go:embed dashboard/*` + `fs.Sub(..., "dashboard")`. Текущий состав:

- **Шапка** — название флоу (`#flow-name`) и индикатор состояния WebSocket-соединения (`#ws-status`,
  тексты `LINK`/`OFFLINE`), управляемый `connectWS()`: автопереподключение с экспоненциальным backoff
  (старт 1с, удвоение, cap 10с) при разрыве соединения.
- **Левая панель** — список стадий (`#stages-list`).
- **Центральная панель деталей** — Plan (рендер через `markdown-it`), кнопки Approve / Send revision / Retry,
  диалоговый канал (история вопросов/ответов, текущий вопрос с опциями и полем произвольного ответа,
  комментирование строк плана), лог.
- **Правая панель** — Event feed.
- **Футер** — прогресс, время старта, elapsed.
- **Панель потребления** (выезжающая слева по кнопке-стрелке) — переключатель метрик tokens/cost/kb (опция
  "деньги" скрывается на клиенте, если `/api/usage?metric=cost` возвращает пустой массив), фильтр по
  стейджам, hand-rolled SVG-график временного ряда.
- Данные: `fetch /api/*` (поллинг) + `WebSocket /ws`. Темы: `novacorps` (`style.css`, по умолчанию) и `goga`
  (`style-goga.css`, подключается server-side клеточкой `pkg/server` при `theme=goga`).

Логика полностью в одном файле без сборки/бандлера, без TypeScript, без компонентной модели — расширение
и поддержка усложняются с ростом функциональности (недавний пример — добавление панели потребления).

## Description

Переписать `pkg/web/dashboard` на React как Vite SPA (статическая сборка, **без SSR**) с полным
поведенческим паритетом текущему `app.js`. Компоненты — на TypeScript (`.tsx`), с сохранением текущих
глобальных стилей и className-структуры, чтобы серверная инжекция goga-темы продолжала работать без
изменений на стороне `pkg/server`.

## Scope

**In scope:**
- Vite + React + TypeScript SPA, сборка в статический вывод в корень `dashboard/` (без отдельной `dist/`),
  чтобы `pkg/web/embed.go` (`//go:embed dashboard/*`) остался без изменений
- Компонентное разбиение UI: список стадий, панель деталей (Plan/Markdown, Approve/Revise/Retry, диалоговый
  канал, лог), event feed, футер, панель потребления (переключатель метрик, фильтр стейджей, SVG-график)
- Кастомные хуки для поллинга `/api/*` и подписки на `WebSocket /ws`
- Сохранение обеих тем (`novacorps` по умолчанию, `goga` через серверную инжекцию `style-goga.css`) без
  изменений в `pkg/server`
- `markdown-it` сохраняется как единственная сторонняя рантайм-библиотека рендеринга (тот же движок и та же
  конфигурация `{ html: false, linkify: true }`, обёрнута в компонент); подключается как обычная
  npm-зависимость вместо текущего вендоренного `markdown-it.min.js` — `public/markdown-it.min.js`
  удаляется, `<script src="markdown-it.min.js">` убирается из `index.html`
- Тесты на Vitest + React Testing Library с покрытием компонентов и хуков
- Usage-файлы для новых зависимостей в `.goga/usages/cooks/` (react, vite, typescript, vitest — уже
  созданы в рамках этой задачи)

**Out of scope:**
- SSR / Next.js — только статический SPA-вывод
- Изменения backend / `pkg/server` (API-контракты, WebSocket-протокол, серверная инжекция темы остаются как
  есть)
- Изменения `pkg/web/embed.go`
- Новые UI-фичи — только переписывание с сохранением поведения 1:1
- Новые сторонние JS-библиотеки, кроме React и сохранённого `markdown-it` (график остаётся собственным SVG,
  без charting-библиотеки)
- Redux/Zustand или любой сторонний менеджер состояния — состояние живёт в React-хуках

## Acceptance Criteria

- `npm run build` в `dashboard/` производит статический бандл (`index.html` + `assets/*`) прямо в корне
  `dashboard/`, потребляемый `pkg/web/embed.go` без единой правки этого файла
- Все перечисленные в Current State UI-элементы и поведение воспроизведены 1:1: шапка (название флоу,
  индикатор состояния WebSocket `LINK`/`OFFLINE`), список стадий, панель деталей (Plan-markdown,
  Approve/Send revision/Retry, диалоговый канал с опциями/своим ответом/комментированием строк, лог),
  event feed, футер (прогресс/старт/elapsed), панель потребления (свитч метрик tokens/cost/kb со
  скрытием "деньги" при пустом ответе API, фильтр по стейджам, SVG-график)
- Поллинг `/api/*` и подписка `WebSocket /ws` работают идентично текущей реализации, включая
  автопереподключение с экспоненциальным backoff и индикацию состояния соединения (`LINK`/`OFFLINE`)
- Обе темы (`novacorps`, `goga`) визуально идентичны текущим — серверная инжекция `style-goga.css`
  продолжает работать без изменений в `pkg/server`
- `npx vitest run` проходит без ошибок, ключевые компоненты и хуки покрыты тестами
- Никакой SSR-инфраструктуры, никаких новых рантайм-зависимостей кроме React и `markdown-it`

## Stack

- **Фреймворк:** React 18+ (функциональные компоненты, хуки)
- **Сборщик:** Vite 5+ + `@vitejs/plugin-react`
- **Язык:** TypeScript 5+ (`.tsx`/`.ts`), строгий режим
- **Тесты:** Vitest 1+ (совместим с Vite 5) + React Testing Library
- **Рендер markdown:** `markdown-it` (тот же движок и конфигурация, подключается как npm-зависимость)
- **Стили:** существующие глобальные CSS-файлы (`style.css`, `style-goga.css`), без CSS-in-JS/CSS
  Modules/Tailwind

## Risks and Constraints

- Проект сейчас не имеет `package.json`/бандлера — вводится с нуля вместе с этой задачей
- Отступление от общего конвеншена `conventions.md` (Jest, JS без TypeScript) — для `pkg/web/dashboard`
  явно используются TypeScript и Vitest вместо Jest; отступление зафиксировано и обосновано в
  `.goga/usages/cooks/vitest.md` и `.goga/usages/cooks/typescript.md`, распространяется только на эту
  клеточку
- Критично сохранить контракт `pkg/web/embed.go` (`//go:embed dashboard/*` + `fs.Sub`) — выходная
  директория сборки обязана совпадать с текущей структурой (`build.outDir` = `.`, `emptyOutDir: false`)
- Полный поведенческий паритет — риск регрессий в менее очевидных сценариях (комментирование строк плана в
  диалоговом канале, скрытие метрики "деньги" при пустом ответе API, double-mount эффектов в
  `React.StrictMode` для WebSocket/поллинга)
- Переход `markdown-it` с вендоренного `markdown-it.min.js` на npm-зависимость — версия пакета из npm
  должна быть зафиксирована так, чтобы конфигурация `{ html: false, linkify: true }` давала идентичный
  вывод HTML на существующих данных (planы/фидбек), иначе возможна регрессия рендеринга markdown
- `build.outDir: '.'` + `emptyOutDir: false` (обязателен, чтобы Vite не стирал `src/`/`public/`/конфиги при
  пересборке) означает, что хешированные по содержимому файлы `assets/*.js`/`assets/*.css` от предыдущих
  сборок не удаляются автоматически и накапливаются в `dashboard/assets/`, молча раздувая бинарник через
  `//go:embed dashboard/*` — требуется отдельный шаг очистки `dashboard/assets/*` перед каждой сборкой
  (например `predist`/`clean:assets` npm-скрипт, удаляющий только сгенерированную папку `assets/`)
