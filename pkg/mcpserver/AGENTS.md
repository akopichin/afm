# MCP server

Пользовательское поведение: [MCP](../../docs/mcp.md). HTTP-границы (`localGuard`,
маршрут, shutdown) — [server](../server/AGENTS.md).

- Сервис привязан к одному ран-у на всю жизнь; repeat-цикл получает новый `Service` и
  новые сессии. Управляющие вызовы сверяют `run_id` и отвечают `run_changed`.
- Группы (`reply`, `stages`, `approve`, `budget`) внутри `ParseGroups` задаются явно,
  «all» нет; слово `read` значит «только чтение» и не смешивается с группами. «По
  умолчанию все группы» — решение уровня CLI (`AllGroups`), не парсера. Инструмент
  регистрируется только при включённой группе, но проверка группы остаётся и внутри
  вызова. Чтение всегда доступно.
- `Catalog()` и `ResourceTemplates()` — единственный источник имён, описаний, схем,
  групп и `RunBound` инструментов: `Service` регистрирует из них, а host пересылает те
  же инструменты. Новый инструмент добавляй в каталог, обработчик — рядом с кодом.
- Approve идёт только через `Approval.ApproveExpected` с ревизией, которую клиент прочитал.
  `StageCommands` намеренно без legacy `Approve`.
- Артефакт читается по непрозрачному id, который резолвится только в plan, summary,
  картинку стадии или объявленный `./`-артефакт, через `os.Root` run-каталога.
  Клиентский путь не принимается; логи и dialog-файлы не читаются. Сохраняй лимиты
  размера и страниц, маскирование секретов (ревизия плана считается по исходным байтам).
- Notifier — одна горутина, стартует при первой подписке или wait. Он берёт baseline до
  ответа клиенту и дополнительно опрашивает состояние: вопросы приходят файлами, а bus
  теряет события для медленного подписчика. Доставка уведомлений best effort.
- `Close` отклоняет новые запросы, прерывает сетевой ввод-вывод, освобождает wait и
  стримы и ждёт все хендлеры до возврата: после него ничто не читает состояние рана.
  Тесты закрывай через cleanup с ожиданием, а не по таймауту.
- Новые коды ошибок общие с REST там, где REST уже называет сбой (`ClassifyEngineError`);
  собственные коды MCP — только для того, что в REST не существует.
