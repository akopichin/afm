# AFM Desktop v0.0.1

The first delivery is a local macOS application. A person opens AFM Desktop.app, selects a folder, starts an AFM run and operates its dashboard and live browser in the same project window. Electron supplies Chromium. The app bundle carries the matching AFM executable, including its dashboard. Users can open a run's loopback URL in their own browser concurrently.

The same verified URL and port open in an external browser. Offer stop/cancel for managed runs and only supported operations for attached runs. Reuse the recorded source and worktree, keep the pipeline snapshot and follow the replacement process of the same run. Offer Delete run for stopped Desktop runs with confirmation. Remove the selected run data and its clean dedicated worktree. Keep shared worktrees and unmerged Git branches. Show reconnect, finished, offline and API-only states accurately. A stale port must never display a different run. |
| DS-04 | Retain the approved Home project tiles, active/attention states, spacing, Graphite controls and workspace composition. Use the AFM hexagon and dot for the application icon. On macOS, use a translucent draggable title bar with native window controls and respect reduced transparency. In the embedded dashboard, start the header with the run title and preserve the run controls. Search projects using the fast overlay. The only persistent left rail inside a run is the existing AFM stage list. The real dashboard owns stage rendering. Reuse repository skin assets and semantic tokens. Custom selects support keyboard and pointer. The assistant is a right drawer with a thin left grip that turns blue on hover/focus. Persist width and clamp it on resize. The drawer has Chat and Tasks tabs; Tasks shows an unread count, and chat shows compact result cards. With the AFM dashboard focused, Desktop reserves the primary modifier with H, J, K, M, Shift+K, comma or 1–9, plus Alt/Option A at the Electron input boundary. Focus mode affects the entire window. Next/previous visit the stable outstanding queue, including multiple stages in a run. Viewing a notice preserves unresolved work. Reply/approval, reconnect and external changes update the queue without duplicates. |
| DS-07 | First launch discovers authenticated Claude Code, Codex and other available providers; allow manual executable/endpoint and credential-reference setup and testing. Persist model, reasoning, provider and permission mode. Offer the provider default, listed models, and a custom model ID. Codex choices come from the installed client's account-specific list. Show the outgoing message and clear the composer as soon as the user sends it. Restore the text when submission is refused and show the error with the message. The app-wide assistant streams actual replies, supports cancellation and uses AFM MCP to inspect or control the selected project/run. Show effective scope before an operation, and surface tool errors. Support provider default, approval and explicit provider-supported unrestricted/YOLO modes. Map flags from installed CLI capabilities and show the selected effective mode. Never log or persist token values in renderer storage or argv. Reopen chat or switch models with a shortcut. The composer stays usable while the provider warms up. The provider's session reference is stored privately beside the conversation and resumed only when the CLI supports it, provider, scope and effective credential still match, and the CLI is not using its own login (which has no verifiable identity). Otherwise the bounded transcript is sent, including unseen messages. Session identifiers never reach renderer events, history, errors or tool payloads. `/clear` is handled locally: it discards the transcript and session reference together and is refused while a reply is running; background watches are unaffected. |
| DS-08 | When a Desktop-launched AFM stage requests a browser, its real Chromium page appears in a sibling Live tab in that project. User and stage agent operate the same DOM, history and session. Switching to the dashboard preserves the page. Reflect navigation and closure; isolate simultaneous runs/stages. Reconnect without assigning a page to a different stage. Release the target when the owning stage ends. External standalone browsers retain their existing lifecycle. |
| DS-09 | Measure startup, keyboard navigation, cross-project bursts, background work and tab lifetime. Apply the budgets and instrumentation below. Record per-reply timing for receipt, provider ready, first text and environment import (including the login-shell PATH) separately. The watch observer shares the single observation loop: no timer runs without a watch task or notification need, supplemental run reads happen only for an active task, and a watch-burst workload bounds the cost. |
| DS-10 | One native application bundle includes AFM and offline UI assets. User launches it without npm, Go, Homebrew or a separate AFM install. Docker validates logic and package contents. Native Electron smoke runs on the Mac against the built candidate. The development workflow reviews each planned task and asks for approval of the exact integration candidate before merging. A successful overnight run on a Mac ends with a locally built, runnable .app from the final revision. Desktop releases publish macOS and Linux archives for arm64 and x64. The macOS app has an ad-hoc signature and a Homebrew cask. Notarization and Windows packaging are follow-up work. |
| DS-11 | In Settings, import exported variables from zsh or bash startup files, load a dotenv file, and add or remove individual variables. Manual entries take precedence over the file, the shell and inherited environment, in that order. Show variable names in Settings. Desktop prepends its browser wrapper to the effective PATH and keeps shell or user PATH entries. New assistant requests use the updated environment. An existing host applies updates after restart. Existing runs retain the environment they started with. AFM's default secret resolution uses the project's secrets.env, then the user-level secrets.env, then the host environment. An explicit secrets-file override retains AFM's existing behavior. The imported shell environment is cached in memory with single-flight imports and copy-on-read results. The cache is invalidated by Desktop environment settings, the dotenv file or shell startup files (including a ZDOTDIR the shell reports), and by an explicit Refresh in Settings → Environment. Failures are never cached. Quit is terminal: it stops running importer shells and starts no new ones. |
| DS-12 | Edit pipeline options from Library or the project launch dialog. Missing preflight requirements open the editor with the reason. | DS-13 | Deliver native system notifications for enabled attention categories while the app is running, using one slower observation loop while hidden. Keep the in-app queue and use stable question identity across pause and reconnect. Clicking a banner opens its run and stage, including after a temporary host outage. If the request is resolved, open the run. Suppress banners for runs already shown in the focused window and keep action text inside Desktop. On macOS, show an amber Dock dot while enabled questions, approvals, or decisions are pending, and briefly bounce the icon for new requests received in the background. Banners for background watch tasks use fixed text with no question text, artifacts or secrets, and show one banner per event. A watch announces only the events it covers, and these banners ignore notification preferences because the user asked for them explicitly. Clicking a stage event opens its run and stage, and clicking a finished or summary banner opens Tasks. Activating the app (Dock) restores the window and refreshes at once. |
| DS-14 | Create background watch tasks from chat with the `desktop_watch_create` tool, or manage them in Tasks (`desktop_watch_list`, `_pause`, `_resume`, `_stop` are also available in every permission mode; they are observation only). A task covers all projects, one project or one exact run (run ID plus instance ID), bounded by the conversation scope. It reports question, approval, decision, failed and finished events, may have a deadline (judged by poll time) and a summary time. Tasks include externally launched discovered runs and API-only runs through identity-checked reads without attaching. Tasks persist in `~/.afm/desktop/watch-tasks.json`, separate from the chat transcript, and survive `/clear` and restarts. Pause, resume and stop keep collected results; events during a pause or while Desktop is closed are not reported. Routine events make no model call. Scheduled summaries use a read-only, tool-less model reply in a separate conversation, with a deterministic plain-text fallback. Reports render a safe Markdown subset (code, details, run links, diagram text fallback) with all HTML escaped. Results show in the Tasks history; opening a result clears its unread state. Limits: 50 tasks, 200 results per task, the 20 newest summaries kept per task. |
| DS-15 | Costs screen from Home and from each project tile. Show spend, tokens, Elapsed, Idle and Stage work for the runs Desktop observes, since each run started, over the last 24 hours or 7 days, and as of any moment in the last 7 days (As of slider with the local date, time and zone, and Back to now). Home tiles draw one cumulative 24-hour line per active run with the since-start total in the legend; without prices they show Stage work. Compare two runs side by side with explicit missing markers and a percentage only for a positive base and comparable estimates. Hide prices removes every price from the page and from stored history. AFM is unchanged: Desktop reads existing status and analytics, keeps its own aggregate history in `~/.afm/desktop/costs-history.json` (at most 50 followed runs and seven days, thinned; a new run waits unrecorded until a finished, vanished or offline run frees a place) and never presents unobserved time, a gap, a reset or a missing figure as zero. Collection runs only while Home or Costs is shown and the window is visible; the live range and Home tiles re-read recorded history at most every 15 seconds, and a fixed As of moment is read once. A run-level Running time does not exist in AFM, so Desktop shows Stage work. Past moments show recorded totals only: stages, overhead and estimate coverage are not stored. |

## Performance acceptance

Run the same workload before and after changes and report OS, architecture and runtime version. Inventory workload is 100 projects and 1,000 runs, warm up then record p50 and p95 over at least 50 samples. The seed gate is p95 under 50 ms with zero render/persistence updates for identical results. Add burst tests for notice ordering, streamed chat and repeated project switches. Count outstanding requests, subscribers and native targets after 100 switches. Keep idle discovery single-flight, suspend unnecessary hidden work, coalesce updates, bound caches and close subscriptions. Hidden active stage pages keep their workflow alive.

On a Mac measure ten packaged launches to usable Home (initial p95 target 3 s) and 100 keyboard switches at idle and during a burst (p95 target 100 ms). Record process-tree RSS before and after opening and closing 20 project tabs. Verify target and listener counts return to baseline and report sustained growth. Report unmeasured native metrics separately from headless figures. Add a watch-burst workload (10 tasks, 1,000 runs): burst poll, store save and idle p50/p95, with no timer while no task exists and no polling while hidden without a need, and a reply-latency workload comparing cold, cached and uncached environment import.
