# AFM Desktop

AFM Desktop is a local macOS and Linux application. A person opens the app, selects a folder, starts an AFM run and operates its dashboard and live browser in the same project window. Electron supplies Chromium. The app bundle carries the matching AFM executable, including its dashboard. Users can open a run's loopback URL in their own browser concurrently.

The Settings title and Close settings button stay visible while the settings body scrolls, including at compact window heights.

## Performance acceptance

Run the same workload before and after changes and report OS, architecture and runtime version. Inventory workload is 100 projects and 1,000 runs, warm up then record p50 and p95 over at least 50 samples. The seed gate is p95 under 50 ms with zero render/persistence updates for identical results. Add burst tests for notice ordering, streamed chat and repeated project switches. Count outstanding requests, subscribers and native targets after 100 switches. Keep idle discovery single-flight, suspend unnecessary hidden work, coalesce updates, bound caches and close subscriptions. Hidden active stage pages keep their workflow alive.

On a Mac measure ten packaged launches to usable Home (initial p95 target 3 s) and 100 keyboard switches at idle and during a burst (p95 target 100 ms). Record process-tree RSS before and after opening and closing 20 project tabs. Verify target and listener counts return to baseline and report sustained growth. Report unmeasured native metrics separately from headless figures. Add a watch-burst workload (10 tasks, 1,000 runs): burst poll, store save and idle p50/p95, with no timer while no task exists and no polling while hidden without a need, and a reply-latency workload comparing cold, cached and uncached environment import.
