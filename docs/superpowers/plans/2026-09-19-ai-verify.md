# AI-verify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: используйте superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans, чтобы исполнять этот план задача-за-задачей. Шаги помечены чекбоксами (`- [ ]`) для трекинга. Коммиты и комментарии — на русском; код и имена символов — как в кодовой базе.

**Goal:** после завершения работы стадии AFM запускает независимую проверку (shell и/или другим агентом, например Codex), сохраняет структурированный результат и возвращает доказуемые blocking-замечания владельцу выполнения через существующую incomplete-политику retry — без нового FSM-статуса, без второго orchestration-engine и без нового retry-loop.

**Architecture:** verify — это **условие завершения стадии**, а не новый stage/agent/phase. Один нормализованный `flow.VerifySpec` (scalar/object/list) описывает последовательность shell- и AI-шагов. Оркестратор (`pkg/orchestrator/verify.go`, новый) делает один проход списка после успешного файлового probe, маппит исходы, при `needs_changes` кладёт durable feedback и возвращает типизированное incomplete-отклонение прежнему владельцу. AI-шаг исполняется существующим `executor` в ограниченном read-only режиме с отдельным захватом финального JSON. Общий агентный запуск строится поверх **PhaseExecutor (Фаза 1)**, которая выполняется в этой же ветке как фундамент (Пакет P0).

**Tech Stack:** Go 1.x (не менять версию в go.mod), `pkg/flow` (YAML+validate), `pkg/orchestrator` (FSM/retry/recovery/concurrency), `pkg/executor` (subprocess lifecycle), `scripts/codex-as-claude.sh` (Codex-адаптер), `schema/flow.schema.json` + `pkg/schemacheck` (drift-guard), React dashboard (`pkg/web/dashboard`).

**Spec:** `tmp/AFM_AI_VERIFY_IMPLEMENTATION_PLAN_v2.md` (spec of record; план ниже аргументирует от него и привязывает его предложения к реальным символам кода). PhaseExecutor Фаза 1: `docs/superpowers/plans/2026-09-19-phase1-phaseexecutor.md`.

## Global Constraints

- **Не менять версию Go в go.mod** без предупреждения (глобальное правило).
- **Нет нового FSM-статуса** `verifying`, нет новых scheduler-переходов, нет второго provider/config registry, нет новых retry-настроек (`verify.retries`/`verify_max_retries`/`on_fail`/`mode`/`required`/`parallel`). [I20]
- **Verify не владеет completion/FSM.** Verify не публикует `EventAgentCompleted`, не делает `EvComplete`, не активирует зависимые стадии. Это делает прежний владелец выполнения. [I03]
- **Один источник истины по verify-спеке** — `flow.VerifySpec`. Не хранить одновременно legacy `string` и новый объект в двух полях.
- **File probe не запускает AI-процесс.** GET/status/refresh и повторная проверка открытого вопроса не должны порождать дорогостоящий verify-вызов. [I04]
- **Один проход verify не содержит собственного correction-loop.** `needs_changes` → типизированное отклонение → существующий `attempt == 0` incomplete-retry (retry.go:160). [I05]
- **Pass принимается только из текущего успешного invocation.** Старый `result.json` рядом с непустым summary/`.done` — не разрешение завершить стадию. [I06] [I15]
- **Error/inconclusive/interruption/ненулевой exit процесса verifier никогда не трактуются как pass.** [I07]
- **Verifier не меняет код/тесты/`.done`/summary/plan/человеческий feedback/память** и не наследует session/роль/права автора. Prompt-only запрет не выдавать за техническую изоляцию. [I11] [I12]
- **При смене команды (автор→verifier) одновременно удерживается не более одного command-slot.** [I13]
- **Pause/cancel останавливает и ожидание ресурса, и процесс проверки.** [I14]
- **Человеческий и машинный feedback не подменяют друг друга** (не писать verify-замечания в `feedback.md` через `SaveFeedback`). [I09]
- **Flow без verify — никакого нового поведения, файлов, defaults.** [I01] [I02]
- **Русский** — комментарии, тексты ошибок пользователю (по образцу существующих), сообщения коммитов. Код максимально понятный человеку.
- **Линт зелёный** после каждого шага (`make lint-ci`); `make test` использует `-race`.

```go
type VerifyKind int
const ( VerifyShell VerifyKind = iota; VerifyAgent )

type VerifyStep struct {
    Kind    VerifyKind
    Run     string        // shell: непустая строка (kind==VerifyShell)
    Command string        // agent: yaml "command" — выбор проверяющего (kind==VerifyAgent)
    Prompt  string        // agent: доп. критерии (опционально)
    Timeout time.Duration // опционально; 0 = не задан; отрицательный отклоняется
}

type VerifySpec struct {
    Steps      []VerifyStep
    fromScalar bool // только для совместимого экспорта; НЕ влияет на выполнение
}

func (s VerifySpec) IsEmpty() bool          // len(Steps)==0
func (s *VerifySpec) UnmarshalYAML(*yaml.Node) error
func (s VerifySpec) validate(stageID string) error // 1-based индексы в сообщениях
```
