# Дизайн: корректный рендер markdown в веб-интерфейсе

Дата: 2026-06-12

## Проблема

Веб-интерфейс flowManager (`pkg/web/`) рендерит markdown самописным парсером в `app.js`,
который понимает только часть синтаксиса: заголовки `##`/`###`, `**bold**`, `` `code` ``,
код-блоки, чекбоксы и плоские списки. Всё остальное — таблицы, вложенные и нумерованные
списки, ссылки, курсив, цитаты — показывается как сырой текст.

Хуже всего в зоне диалога с агентом: сообщения `agent_text` и тексты вопросов вставляются
как plain text (`textContent`), markdown там не рендерится вообще. Длинные сообщения
агента с заголовками, списками и таблицами выглядят кашей.

## Решение

Подключить библиотеку **markdown-it** (последняя стабильная 14.x) одним вендоренным
минифицированным файлом. Самописный блочный парсер удалить. Альтернативы рассмотрены
и отклонены: дописывать свой парсер — бесконечные краевые случаи; серверный рендер
через goldmark — усложняет API (режиму ревью всё равно нужен сырой текст).

### 1. Подключение библиотеки

- Файл `pkg/web/markdown-it.min.js` (вендорится как есть, без билд-процесса).
- Добавить в директиву `go:embed` в `pkg/web/embed.go`.
- Подключить `<script src="markdown-it.min.js">` в `index.html` перед `app.js`.
- Инициализация: `html: false` (сырой HTML экранируется — безопасно без санитайзера),
  `linkify: true` (голые URL становятся ссылками).

### 2. Просмотр плана — `renderMarkdown()`

- Тело функции заменяется на рендер через `md.render(text)`.
- Спецсекции (assumptions/criteria, `detectSection`) сохраняются: текст предварительно
  режется по заголовкам секций, каждый кусок рендерится библиотекой отдельно
  и оборачивается в существующие `plan-section-wrapper` / `plan-section-body`
  с кликабельным заголовком-сворачивалкой.
- Чекбоксы `[x]` / `[ ]` заменяются на спаны `cb-done` / `cb-open` постобработкой
  отрендеренного HTML (как сейчас, но по результату рендера).
- Всем ссылкам проставляется `target="_blank" rel="noopener"`, чтобы переход
  не терял состояние страницы.

### 3. Диалог с агентом

- Сообщения `agent_text` в истории: `md.render(e.text)` вместо `textContent`.
- Тексты вопросов — в истории (`.q`) и в pending-панели (`.dialog-question`):
  тоже полный рендер через `md.render()`.
- Ответы (`.a`) и кнопки-опции остаются plain text (это короткие строки,
  кнопкам markdown не нужен).

### 4. Режим ревью — `renderPlanReview()`

- Остаётся построчным: каждая строка — отдельный div с номером, это требование
  привязки инлайн-комментариев к строкам. Библиотека сюда не встаёт по построению.
- `inlineFormat()` переводится на `md.renderInline(line)` + замена чекбоксов:
  строки получают курсив, ссылки и корректный инлайн-код вместо трёх regex'ов.
- Блочная структура (`formatLine`, код-блоки, секции) не меняется.

### 5. CSS

В `style.css` добавляются стили в существующей тёмной палитре для элементов,
которых раньше не было: `table` (рамки, зебра), `blockquote`, `em`, `a`,
`ol` и вложенные `ul`/`ol`, `hr`.

### 6. Что не меняется

- Go-код, кроме одной строки в `embed.go`.
- API сервера: план и диалог по-прежнему ходят сырым markdown-текстом.
- Рендер логов (`$logContent`) — это логи, не markdown.
- Построчная механика комментариев в режиме ревью.

## Тестирование

JS-тестов в проекте нет, проверка ручная:

1. `go build ./...`, линт, существующие Go-тесты (`pkg/server`) — без регрессий.
2. Открыть UI на ране с планом, содержащим таблицы, вложенные/нумерованные списки,
   ссылки, курсив, цитаты — всё рендерится корректно.
3. Диалог с вопросами агента: длинное сообщение `agent_text` с markdown читаемо.
4. Режим ревью (`awaiting_approval`): строки нумеруются, комментарии добавляются,
   инлайн-форматирование работает.
5. Проверить, что сырой HTML в тексте плана экранируется (не исполняется).
