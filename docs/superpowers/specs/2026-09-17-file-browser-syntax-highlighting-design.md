# File-browser syntax highlighting: yaml / markdown / bash

**Date:** 2026-09-17
**Type:** bounded change (extends an existing subsystem — the Docker Project File Browser)

## Goal

The dashboard file browser must syntax-highlight the following languages:
**go, ts, js, yaml, md, bash**.

Of these, go / ts / js are already highlighted today. This change adds
**yaml, markdown, bash**.

## Current state

- **Backend** — `pkg/server/workspace/language.go`, `detectLanguage(name)` maps a
  file's extension to the highlight.js language id the frontend expects:
  - `.go` → `go`
  - `.ts`, `.tsx` → `typescript`
  - `.js`, `.jsx`, `.mjs`, `.cjs` → `javascript`
  - `.py`, `.pyi` → `python`
  - else → `plain`
- **Frontend** — `pkg/web/dashboard/src/components/file-browser/highlight.ts`
  registers exactly those four grammars from `highlight.js/lib/core` (core, not
  `index.js`, so the bundle carries only the grammars we register — not all ~190).
  `highlight(language, source)` returns highlighted HTML for a registered
  grammar, else `escapeHtml(source)`. Its output is the ONLY value allowed into
  `dangerouslySetInnerHTML` (`FileViewer.tsx`); hljs escapes found text itself.
- **CSS** — `pkg/web/dashboard/skins/base/file-browser.css` defines a
  theme-aware, tokenized hljs palette (no hardcoded hljs theme): keyword /
  built_in / type, string / regexp / template-string, comment / quote, number /
  literal, title, tag / name / attr, symbol / bullet / meta / deletion,
  addition, emphasis, strong. Adapts across every skin × light/dark.

The backend id and the frontend registration name are the same string and MUST
stay in sync — the id `detectLanguage` returns is what `hljs.registerLanguage`
is keyed on, and what `highlight()` looks up via `hljs.getLanguage`.

## Design

### 1. Frontend — register three more grammars (`highlight.ts`)

Add imports + registrations:

```ts
import bash from 'highlight.js/lib/languages/bash'
import markdown from 'highlight.js/lib/languages/markdown'
import yaml from 'highlight.js/lib/languages/yaml'

hljs.registerLanguage('yaml', yaml)
hljs.registerLanguage('markdown', markdown)
hljs.registerLanguage('bash', bash)
```

Update the header comment: "4 грамматик" → 7 (go / typescript / javascript /
python / yaml / markdown / bash). No other logic changes — `highlight()`,
`splitHighlightedLines()`, `escapeHtml()`, and the `dangerouslySetInnerHTML`
safety contract are untouched.

### 2. Backend — map the new extensions (`language.go`)

Add cases to `detectLanguage`:

- `.yaml`, `.yml` → `yaml`
- `.md`, `.markdown` → `markdown`
- `.sh`, `.bash` → `bash`

The returned id matches a registered grammar name. Extension-based detection
only (no shebang / content sniffing) — consistent with the existing switch and
enough for the target set.

### 3. CSS — cover the few new token classes (`file-browser.css`)

yaml emits tokens already in the palette (`hljs-attr` for keys, `hljs-string`,
`hljs-number`, `hljs-bullet`, `hljs-meta`, `hljs-literal`). markdown and bash
emit a few classes not yet in the palette; without a rule they fall back to the
base text color — readable but uncolored. Add them so md/bash render fully:

- `hljs-section` — markdown headings
- `hljs-code` — markdown inline / fenced code
- `hljs-variable` — bash `$var`
- (`hljs-link` — markdown links, optional)

Add `hljs-link` (markdown links) as well — markdown reliably emits it, so it is
part of "render fully", not optional. Use existing semantic tokens (e.g.
`--accent-primary` for headings/links, `--text-primary` or `--attention` for
code/variable) so the additions stay theme-aware like the rest of the palette.
Other classes md/yaml/bash may emit (`hljs-template-variable`, `hljs-char.escape`,
`hljs-subst`) inherit their surrounding string color and stay readable — no rule
needed.

**Edit only the source `skins/base/file-browser.css`.** The tracked
`public/skins/base/file-browser.css` is a GENERATED mirror — `scripts/sync-skins.js`
deletes `public/skins` and re-copies `skins/`. It is regenerated by the build
(see §5), not hand-edited.

### 4. Tests (TDD)

- `highlight.test.ts` — new cases: `yaml` / `markdown` / `bash` each now produce
  at least one `hljs-…` span (previously they'd have gone through the
  unregistered-language `escapeHtml` branch). The existing "unregistered
  language → escaped, no spans" test keeps an id that stays unregistered
  (currently uses `rust`).
- `pkg/server/workspace/language_test.go` — `TestDetectLanguage`. It currently
  asserts `README.md → plain`; that row flips to `markdown`. Add cases for the
  three new languages and their aliases: `.yaml`/`.yml` → `yaml`,
  `.markdown` → `markdown`, `.sh`/`.bash` → `bash`.

### 5. Rebuild the embedded bundle (required, not incidental)

The dashboard bundle is checked into git and embedded into the afm binary
(`pkg/web/embed.go` embeds `dashboard/index.html`, `dashboard/skins`,
`dashboard/assets`). The new grammar imports and CSS do NOT reach a running afm
until the bundle is rebuilt. After the source edits:

```
cd pkg/web/dashboard && npm run build
```

`npm run build` chains `restore-index` + `sync-skins` (regenerates the
`public/skins` mirror) + `clean:assets` + `vite build` (regenerates
`assets/index-*.js` and `index.html`). Those regenerated artifacts are part of
the commit. `highlight.js ^11.12.0` is already a dependency — no new install.

## Decisions

- **Keep `python`.** It is highlighted today; it is not in the requested set but
  dropping it would silently regress `.py` files to plain. Recommendation: keep
  it. (OPEN — awaiting confirmation.)

## Non-goals

- No shebang / content-based language detection.
- No new file types beyond the extensions listed.
- No change to the file browser's security boundary, HTTP surface, or the
  `dangerouslySetInnerHTML` contract.

## Known limitations (documented, not fixed)

`markdown` declares `xml` as a sublanguage (inline HTML) and `yaml` declares
`ruby` for ERB. With `lib/core` and only the seven grammars we register, those
embedded regions are safely escaped but NOT highlighted. We deliberately do not
register `xml`/`ruby` just for these edge cases (bundle cost > value). Acceptable.
