# Dashboard UI-фиксы (батч из 7) — дизайн

**Дата:** 2026-07-21
**Статус:** design (одобрен к реализации)

## Цель

Пользовательские UI-фиксы дашборда (`pkg/web/dashboard`, React/TS). Все — точечные изменения В РАМКАХ существующей дизайн-системы (компоненты, `Maximizable`, `PanelFrame`, plan-comment паттерн, `useThemeMode`/`useStickToBottom`, CODEMANIFEST/.usages конвенции). Никакого нового «смелого» аесетика — следуем существующим паттернам.

## Фиксы

### #1 — Ctrl+Enter отправляет ответ в диалоге
`DialogChannel.tsx`: на `<textarea className="dialog-custom">` (и на textarea комментария из #2) добавить `onKeyDown`: `Ctrl+Enter` или `Cmd+Enter` → вызвать `sendAnswer()`. Не мешает переносу строки обычным Enter.

### #2 — Комментарии к вопросам (как к планам) — killer feature
Переиспользуем plan-comment паттерн из `PlanPanel.tsx` (`parseReviewPlan`/`renderPlanLine`/`comments: Record<number,string>`/`buildFeedback`).
- Текущий вопрос (`pending.question`) рендерится как пронумерованные КЛИКАБЕЛЬНЫЕ строки (как review-план), а не только `MarkdownRenderer`.
- Клик по строке → инлайн-форма комментария (тот же UI, что `line-comment-form` в PlanPanel): add/update/delete, состояние в `comments`.
- **Пока `comments` пуст** — показываются опции + свободный `<textarea>` + кнопка `▸ SEND` (текущее поведение без изменений).
- **Как только написан ≥1 комментарий** — опции и свободный `<textarea>` СКРЫВАЮТСЯ, вместо них одна кнопка **`Send feedback`**. По нажатию: собрать текст комментариев (формат как `buildFeedback`: для каждой прокомментированной строки — цитата строки вопроса + комментарий, напр. `> <line text>\nLine N: <comment>`, отсортировано по номеру, joined `\n\n`) и отправить его как ОТВЕТ: `POST /api/stages/<id>/dialog/answer` c `{id, phase, answer: <feedbackText>, from_options: false}`. Агент читает это как свой ответ.
- Убрал все комментарии (стало 0) → возвращаются опции+textarea.
- Формат ответа: цитата прокомментированной строки вопроса + `Line N: <comment>` (даёт агенту контекст, к чему комментарий). Подтверждено пользователем.

### #3 — Тёмная тема по умолчанию (не из системы)
Bootstrap темы (инлайн-скрипт в `index.dev.html` + `public/index.html`, и/или `useThemeMode`): при ОТСУТСТВИИ сохранённого в localStorage выбора использовать `dark` (сейчас: `localStorage → matchMedia(prefers-color-scheme) → light`). Ручной toggle (☾/☀ в футере) СОХРАНЯЕТСЯ — пользователь может переключиться на светлую; убираем только дефолт-из-системы/светлую. Белая тема НЕ удаляется.

### #4 — Логи: на весь экран + меньше резать
`LogPanel.tsx`: обернуть в `<Maximizable id="logs">` + `PanelFrame maximizeId="logs"` (как `dialog`/`plan`), чтобы появилась кнопка «на весь экран». Увеличить длину строки до обрезки (текущее значение усечения поднять; точное число — на этапе плана по коду); при развёрнутом (maximized) состоянии — не обрезать вовсе (полные строки).

### #5 — Название/описание проекта в хедере
`FlowHeader.tsx`: выводить `description` из корня flow/проекта в верхнем хедере (чтобы различать несколько запущенных пайпов). Данные уже приходят (flow parsing) — пробросить в компонент и отрендерить рядом с существующим заголовком.

### #6 — Перевести «к последнему»
`DialogChannel.tsx:201`: `↓ к последнему` → `↓ latest` (в event-feed кнопке — проверить, есть ли такая же строка и там; перевести все вхождения).

### #7 — Скролл диалога в конец при раскрытии
`DialogChannel.tsx` уже держит хвост через `useStickToBottom` + rAF `jumpToBottom` при новом вопросе. Гэп: при РАСКРЫТИИ (maximize) скролл не в конце. Решение: при переходе `Maximizable(dialog)` в развёрнутое состояние вызвать `jumpToBottom()` (rAF после layout). Механизм связи maximize→скролл уточняется по коду `Maximizable`/`useStickToBottom` на этапе плана.

## Тестирование

Фронтенд: `npm run typecheck` + `npm test` (vitest) в `pkg/web/dashboard` — зелёные. Каждый нетривиальный фикс — покрыт тестом (у компонентов есть `*.test.tsx`): #1 (Ctrl+Enter триггерит send), #2 (комментарий → textarea исчезает → Send feedback шлёт joined-текст как answer; удаление всех комментариев возвращает опции), #4 (LogPanel имеет maximize-кнопку), #5 (header содержит description), #6 (строка переведена), #7 (при maximize вызывается jumpToBottom). #3 — тест дефолта темы (нет localStorage → dark).

После правок — пересборка дашборда (`npm run build`), т.к. корневые артефакты эмбедятся через go:embed (см. dashboard build-конвенцию: `outDir: '.'`, `public/` → корень). Backend `go build`/`go test` не затрагиваются.

## Границы
Только `pkg/web/dashboard`. Существующие CODEMANIFEST/.usages задетых компонентов обновить, если меняется их публичное поведение. Никаких изменений бэкенда/API (эндпоинты `/dialog/answer`, `/revise` уже существуют). `accept.yaml` не трогать.

## Реализация
Один спек → один план. Subagent-driven: тривиальные (#6, #1, #3, #5, #7) сгруппировать; #2 (killer feature) — отдельная задача; #4 — отдельная небольшая. Порядок: сгруппированные мелкие → #4 → #2.
